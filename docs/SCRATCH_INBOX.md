# صندوق پیام مدیر در اندروید

آیکون پاکت در پایین چپ صفحهٔ Home است. تعداد پیام نخوانده با ارقام فارسی نشان داده می‌شود؛ با لمس آن دیالوگ مناسب لنداسکیپ باز می‌شود. در عرض کم، فهرست و جزئیات پشت‌سرهم و در عرض کافی کنار یکدیگرند. پیام خودکار روی صفحه نمی‌پرد و صدایی پخش نمی‌کند.

متن، تصویر اختیاری، تاریخ شمسی، سنجاق و حداکثر دو دکمهٔ لینک HTTPS پشتیبانی می‌شوند. باز کردن جزئیات پیام یا «همه را خواندم» فقط وضعیت محلی را تغییر می‌دهد؛ سرور آمار خواندن کاربران دریافت نمی‌کند. ویرایش معمولی پیام باعث نخوانده‌شدن مجدد نمی‌شود، مگر مدیر گزینهٔ اعلان مجدد را فعال کند.

## قرارداد API

ریشه همان BuildConfig.COURSE_API_BASE، شامل /scratch/v1 است:

```text
GET /inbox/public?flavor=bazaar&version=<VERSION_CODE>
GET /inbox/personal?flavor=bazaar&version=<VERSION_CODE>
X-Scratch-Account: <existing account secret>   # personal only
If-None-Match: <ETag>                         # optional
```

پاسخ data شامل schema=1، complete=true، scope، account_uuid (فقط شخصی)، flavor، version_code و messages است. هر پیام:

- id (UUID)، revision، notification_version
- title، body (متن ساده)، kind (info/celebration/lesson/warning)، pinned
- published_ms، expires_ms اختیاری، date_label شمسی
- buttons شامل label و url، حداکثر دو مورد
- image اختیاری شامل url، sha256، bytes، width، height و mime=image/webp

سرور فقط پیام‌های منتشرشده، معتبر در زمان و مناسب استور/نسخه را برمی‌گرداند. پاسخ کامل ممکن است خالی باشد؛ یعنی پیام‌های قبلی باید کنار بروند. سقف هر snapshot صد پیام است. 304 یعنی از snapshot معتبر قبلی استفاده کن؛ پاسخ ناقص یا ناسازگار هرگز جایگزین کش نمی‌شود.

## عملکرد و حریم خصوصی

- دریافت و decode روی Dispatchers.IO؛ UI فقط StateFlow را می‌خواند. اول کش و بعد شبکه؛ هیچ سرویس دائمی وجود ندارد.
- حلقه و callback شبکه فقط هنگام RESUMED بودن Home فعال‌اند. ورود، برگشت و اتصال مجدد دریافت را درخواست می‌کنند؛ mutex و فاصلهٔ حداقل ۳۰ ثانیه از تکرار جلوگیری می‌کنند. بررسی عادی هر پنج دقیقه است؛ Retry-After رعایت می‌شود.
- هر دور حداکثر دو درخواست متنی. حداکثر هشت تصویر برای پیش‌دریافت، با دو دانلود هم‌زمان. اتصال چهار و خواندن شش ثانیه؛ بدون دنبال‌کردن redirect.
- سقف JSON چهار MiB، هر عکس یک MiB، کش تصاویر دیسک ۳۲MiB و Bitmap حدود ۶MiB. فایل AtomicFile و hash تصویر بررسی می‌شود.
- کش در noBackupFilesDir و جدا برای هر flavor است. اطلاعات خصوصی و تصویرهای آن AES-GCM/Android Keystore رمز می‌شوند؛ namespace شامل hash حساب و نشست است. public هرگز secret نمی‌فرستد. private فقط روی origin و مسیر مشخص سرور اعتبارنامه می‌فرستد.
- تعویض حساب یا پایان نشست بلافاصله پیام خصوصی را پنهان می‌کند و پاسخ‌های قدیمی را کنار می‌گذارد. کش خصوصی حساب قبل پاک می‌شود؛ read marks رمز‌شده برای حداکثر بیست حساب حفظ می‌شوند.
- قطع اینترنت، خطای سرور و JSON خراب کش معتبر را از بین نمی‌برند. در اولین snapshot موفق، پیام حذف‌شده/لغو انتشار/گیرندهٔ حذف‌شده از لیست و کش عکس کنار می‌رود. حذف سرور در حالت آفلاین فوراً قابل اطلاع نیست.
- خطای دریافت پیام هرگز به‌تنهایی باعث logout نمی‌شود؛ تشخیص پایان نشست اصلی اپ بدون تغییر مانده است.

## فایل‌ها و تست

کد در package inbox، اتصال UI در HomeScreen و پاک‌سازی هویت در LearningIdentity است. پیش‌نمایش‌های InboxUi.kt در اندازه‌های ۹۰۰×۴۲۰ و ۶۴۰×۳۲۰ قابل مشاهده‌اند و شبکه اجرا نمی‌کنند.

```powershell
.gradlew.bat :app:testBazaarDebugUnitTest :app:testMyketDebugUnitTest --offline
```

InboxPolicyTest قوانین unread، badge فارسی، تعویض حساب، انقضا، ترتیب، نرخ درخواست و محدودهٔ URL خصوصی را می‌آزماید. تست parser/Keystore/چرخهٔ واقعی دستگاه جای تست JVM نیست و باید هنگام QA نسخهٔ انتشار روی دستگاه نیز بررسی شود.

پنل سرور: اسکرچ فارسی ← پیام‌های کاربران، /admin/scratch-inbox. راهنمای کامل مدیریت، migration اتصال admin و CDN در docs/SCRATCH_INBOX.md مخزن backend است. این پیام‌ها Push Notification نیستند و فقط نسخهٔ جدید اپ آن‌ها را دریافت می‌کند.
