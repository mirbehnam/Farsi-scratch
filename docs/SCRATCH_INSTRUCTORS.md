# دربارهٔ مدرس

مدیریت پروفایل در پنل سرور `/admin/scratch-instructors` است. هر دوره یک پروفایل اختیاری دارد و هر مدرس می‌تواند چند دوره داشته باشد. نام و نام خانوادگی، عنوان تخصصی، بیوگرافی، عکس و راه ارتباطی را مدیر تنظیم و جداگانه منتشر می‌کند.

## قرارداد

در پاسخ دوره `instructor_profile` اختیاری و nullable است. ساختار:

```json
{"uuid":"12345678-1234-4234-8234-123456789abc","revision":1,"first_name":"بهنام","last_name":"تاج‌الدینی","name":"بهنام تاج‌الدینی","headline":"مدرس اسکرچ","biography":"معرفی مدرس","photo_url":null,"contacts":[{"type":"email","label":"ایمیل مدرس","value":"teacher@example.com","url":"mailto:teacher@example.com"}]}
```

API عمومی مستقل نیز `GET /scratch/v1/instructors/{uuid}` است و بدنه `data` همین پروفایل است؛ پیش‌نویس/غیرفعال 404 می‌دهد. عکس `GET /scratch/v1/instructor-images/{sha256}`، WebP عمومی ۵۱۲×۵۱۲ با ETag و کش یک‌روزه روی همان دامنه API است. عکس به توکن یا حساب نیاز ندارد و از کش عمومی تصویر استفاده می‌کند؛ فرمان پاک‌سازی کش تصاویر آن را هم پاک می‌کند.

اطلاعات پروفایل همراه کش دوره ذخیره می‌شود و بازکردن دیالوگ هیچ درخواست اجباری جدیدی ندارد. بروزرسانی/غیرفعال‌سازی با تازه‌شدن فهرست یا قیمت دوره اعمال می‌شود؛ در قطع شبکه آخرین نسخه کش‌شده حفظ می‌شود. نبود فیلد یا پاسخ ناقص فقط نمایش نام ساده را نتیجه می‌دهد؛ نبود عکس جایگزین حرف اول نام دارد. متن به‌صورت Compose Text است، نه HTML. طول بیوگرافی و آرایه تماس محدود است و URL تصویر باید دقیقاً روی مبدا API و مسیر هش عمومی باشد.

نام مدرس در کارت و مشخصات دوره، دیالوگ بومی مناسب لنداسکیپ را باز می‌کند. قالب HTML با `data-field="instructor"` خودکار به `view-instructor` وصل می‌شود. bridge فقط UUID دوره موجود را قبول می‌کند؛ هیچ اطلاعات حساب یا رسیدی در این پیام نیست. ارتباط‌ها فقط HTTPS، mailto یا tel معتبر هستند؛ ACTION_VIEW شماره‌گیر/مرورگر را باز می‌کند، تماس مستقیم نمی‌گیرد. نبود برنامه مناسب مهار می‌شود و آدرس برای کپی ارائه می‌شود.
