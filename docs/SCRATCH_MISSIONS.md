# مأموریت‌ها در اندروید

ورود: بدج گربه در هوم یا آموزش ← «مأموریت‌ها و جایزه‌ها».

شش مأموریت سروری: اولین ورود برنامه‌نویسی ۱۰، ۳۰ دقیقه برنامه‌نویسی ۵۰، ۱۰ دقیقه ویدیو ۵۰، ۶۰ دقیقه ویدیو ۳۰۰، ورود روزانه ۱۰، تعیین تکلیف اطلاعات تکمیلی ۵۰ XP. فقط ورود روزانه تکرار می‌شود، با مرز نیمه‌شب تهران. زمان قبلی پذیرفته‌شده هم محاسبه می‌شود.

## API

Base: `https://api.behnamapp.ir/scratch/v1`؛ هدر خصوصی `X-Scratch-Account`.

- GET `learning/missions`: فهرست داخل data با uuid، available، day، reset_at_ms، server_time_ms، items.
- POST `learning/missions/visit` با `{}`: ورود آنلاین روزانه؛ پس‌زمینه پس از account موفق. تکرار تا روز بعد با زمان سرور مهار شده و خطا پنج دقیقه cooldown دارد.
- POST `learning/missions/{id}/claim` با `{period: once}` یا day دریافتی سرور: پاسخ awarded، reward_xp، profile، missions. هیچ مقدار XP یا درصد از گوشی ارسال نمی‌شود.

هر item: id، title، metric، progress، target، reward_xp، period، status (active/ready/claimed)، claimed_at. زمان‌ها در metricهای زمانی میلی‌ثانیه‌اند. جایزه دستی است؛ قطع پاسخ با تکرار همان claim امتیاز اضافه نمی‌سازد. تاریخ گذشته daily پس از نیمه‌شب پذیرفته نمی‌شود.

## ایمنی و UX

MissionBoard در LearningStore خصوصی کش می‌شود، با UUID صاحب حساب؛ نشست و UUID پیش و پس از پاسخ کنترل می‌شوند. اطلاعات حساب قبلی در حساب جدید نشان داده نمی‌شود. بازکردن صفحه ابتدا کش را نمایش می‌دهد و از sync محدود موجود برای گزارش‌ها استفاده می‌کند. دریافت جایزه فقط آنلاین است؛ صدای سکهٔ کوتاه به‌صورت محلی تولید می‌شود و خرابی صدا روی XP اثری ندارد. موفقیت/انیمیشن فقط پس از awarded=true است. پاسخ پروفایل با revision قدیمی XP تازه را در کش عقب نمی‌برد.

انتخاب عدم تمایل صریح برای سن، استان و جنسیت در `supplementary.declined_fields` ذخیره می‌شود؛ null بدون این انتخاب به معنای تعیین تکلیف نیست. هیچ اطلاعات شخصی برای جایزه الزامی نیست. دکمه اطلاعات تکمیلی نیز اکنون برجسته است.

پیش‌نمایش: `MissionsPreview` برای کارت active/ready/claimed. تست `MissionPolicyTest` برای تقدم کارت‌ها و محدودبودن درصد. سه فلیور bazaar/myket/website باید کامپایل شوند. بازبینی روی گوشی لنداسکیپ کوچک، حالت قطع شبکه، تعویض حساب، دوبار لمس و صدای خاموش نیز انجام شود.

استقرار سرور: بعد از backup و git pull، `php artisan optimize:clear`، `php artisan scratch:migrate --force`، سپس `php artisan optimize`. worker یا ابزار رسانه لازم نیست. تا قبل از مایگریشن، اپ توضیح آماده‌نبودن مأموریت‌ها را نمایش می‌دهد و خرید/پخش مختل نمی‌شود.
