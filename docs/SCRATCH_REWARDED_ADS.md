# تبلیغ اختیاری جایزه‌ای در مأموریت‌ها

SDK پایدار `com.adivery:sdk:4.9.0` از Maven Central استفاده می‌شود. منبع API: [مستندات رسمی Android ادیوری](https://docs.adivery.com/android). App ID و Placement ID عمومی از پاسخ مأموریت‌های همان حساب می‌آیند. SDK فقط هنگام نیاز در مأموریت‌ها configure/prepare می‌شود، نه در هوم یا هر بار رندر UI. تبلیغ در callback بارگذاری خودکار باز نمی‌شود.

سرور داخل `rewarded_ad` شناسه‌ها، مبلغ قطعی پیشنهادی، تعداد فرصت، طول بازه و زمان آزادشدن فرصت بعدی را می‌دهد. اگر غیرفعال یا سرور قدیمی باشد، کارت تبلیغ نمایش داده نمی‌شود. اگر ویدیو آماده نباشد دکمهٔ مشاهده غیرفعال است؛ نبود موجودی نباید مانع استفاده از مأموریت‌های دیگر شود.

با کلیک اول، مجوز با UUID تصادفی رزرو و دیالوگ جمع‌وجورِ مناسب لنداسکیپ باز می‌شود؛ مبلغ همان رزرو را نشان می‌دهد. با «مشاهده» ابتدا سرور شروع را می‌پذیرد، سپس SDK در صورت `isLoaded` تبلیغ را نشان می‌دهد. «الان نه» رزرو را بدون جایزه لغو می‌کند. مبلغ از کلاینت تعیین نمی‌شود.

هم اعلام نمایش و هم `onRewardedAdClosed(...,true)` لازم است؛ دکمهٔ بستن یا زمان‌سنج ساده به‌تنهایی جایزه نمی‌دهد. SDK ۴٫۹٫۰ روی `AdiveryListener` متد onError ندارد؛ به override ناموجود تکیه نمی‌کنیم. نبود callback نمایش تا ده ثانیه، بدون پرداخت لغو می‌شود.

نتیجهٔ callback پیش از شبکه در `LearningStore` خصوصی و رمزگذاری‌شده ذخیره می‌شود. listener در سطح اپ است و بسته‌شدن دیالوگ، دریافت نتیجه را قطع نمی‌کند. نتیجه با backoff و در مراجعهٔ بعدی به هوم/مأموریت‌ها دوباره ارسال می‌شود؛ یک receipt در انتظار باید پیش از رزرو بعدی تعیین تکلیف شود. نتیجهٔ حساب قبلی روی حساب دیگر ارسال نمی‌شود.

مسیرهای زیر با `X-Scratch-Account` زیر `/scratch/v1/learning/missions` هستند:

| مسیر POST | بدنه |
|---|---|
| `ads/reserve` | `uuid` |
| `ads/start` | همان `uuid` |
| `ads/complete` | همان `uuid` و `is_rewarded:true` |
| `ads/cancel` | همان `uuid` |

شروع مجوز ده دقیقه اعتبار دارد؛ تکمیلِ تبلیغ شروع‌شده تا ۲۴ ساعت امکان retry دارد. سرور سهمیهٔ شناور و پرداخت یک‌باره را کنترل می‌کند. پاداش پیش‌فرض `10 × max(1, level)` سکه **و** XP، حداکثر دو بار در ۱۲۰ دقیقه است؛ مدیر می‌تواند همهٔ این اعداد و فعال‌بودن مأموریت‌های دیگر را تغییر دهد. ساعت مشاهده ویدیو/برنامه‌نویسی با تبلیغ افزایش نمی‌یابد. پاداش سرور پروفایل، سطح و موجودی را تازه می‌کند و جریان موجود صدای سکه را در مأموریت‌ها فعال می‌کند.

این روش SSV ادیوری نیست؛ callback گوشی قابل جعل در کلاینت دستکاری‌شده است. سرور در این نسخه امضای مستقل ادیوری را تأیید نمی‌کند. برای ارتقا ابتدا باید قرارداد رسمی SSV از ادیوری تأیید شود. کلید ثابت مخفی در APK اضافه نشده است. تنظیمات حریم خصوصی/سن مخاطب ناشر باید پیش از انتشار برای مخاطبان نوجوان بررسی شود؛ GAID اختیاری جداگانه برای هدف‌گیری اضافه نشده است.

تست روی گوشی واقعی برای موجودی، نمایش، برگشت از تبلیغ، قطع اینترنت و تأیید حساب ناشر لازم است؛ موفقیت build و تست واحد، نمایش واقعی تبلیغ را تضمین نمی‌کند. برای تست از ابزار/حالت مجاز ادیوری استفاده کنید.
