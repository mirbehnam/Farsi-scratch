# سازگاری با محدودیت ترافیک سرور

- لایه امنیت سرور مستقل از احراز حساب و تأیید خرید است. حفاظت برای همه کلاینت‌ها در سرور اعمال می‌شود، حتی نسخه‌های قدیمی.
- پاسخ `429` یعنی درخواست زیاد؛ `Retry-After` عدد ثانیه را اعلام می‌کند. کلاینت این عدد را با سقف نمایشی یک ساعت نشان می‌دهد؛ اگر موجود نبود مدت حدسی اعلام نمی‌کند. retry خودکار یا حلقه شبکه جدید اضافه نشده است.
- کد `ip_blocked` در پاسخ `403` یعنی محدودیت این شبکه/IP، نه خارج‌شدن از حساب یا باطل‌شدن خرید. متن مناسب نمایش داده می‌شود.
- برای خطای `ip_blocked` دانلود، خرید دوباره بازیابی نمی‌شود؛ رسید تبلیغ در انتظار نیز صرفاً به دلیل این خطا حذف نمی‌شود. برنامه نباید برای دورزدن محدودیت سرور IP یا هدر جعلی بسازد.
- درخواست‌های برنامه‌نویسی/تماشای آفلاین در سازوکار معمول outbox باقی می‌مانند؛ این تغییر هیچ حساب یا ویدئوی کش‌شده را پاک نمی‌کند.
- مستند کامل سیاست، Redis، IP واقعی پشت CDN، نگهداری گزارش و بازیابی در مخزن سرور: `docs/SECURITY.md`.
